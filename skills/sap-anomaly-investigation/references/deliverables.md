# 交付物

產出任何文件、清單前讀這份。

## 共通格式

- 交付文件以 Markdown 為主；給 PM 的版本另出 PDF。用詞固定（同一個概念全文用同一個完整的詞，不要有時寫全名、有時只寫簡稱）。
- **Markdown 表格的儲存格不要塞字，一格只放一句**：Obsidian 的表格不會換行、不能縮排，一格塞兩三句就擠成一團，整張表很難讀。技術筆記的結論總表、操作步驟的步驟總覽、簡明版的表都適用：每格一句結論或摘要，確定性欄只放 ✅🔶❓；證據、細節放在表格正下方，用「**#N**」小標接條列。（給操作人員的 Excel 清單另有規則，見下方）

## 文件清單

| 文件 | 對象 | 內容 |
|---|---|---|
| 技術筆記 | 資訊端 | 機制、證據、結論編號、撤回的結論、待辦、更新紀錄 |
| 正式區資料修正操作步驟（含 PDF） | 資訊端、PM 詳細版 | 步驟總覽與進度、各步驟操作、注意事項、測試紀錄、附錄 SQL |
| 簡明版（含 PDF） | PM | 見下方「簡明版的寫法」 |
| 測試區操作說明（含 PDF） | 操作人員 | 單據清單、步驟、截圖要求、紀錄表、資訊端確認 SQL |
| 修正總表 Excel | 資訊端 | 每份清單一頁，含步驟、判定、處理方式、處理紀錄欄；用來追蹤，不直接發給操作人員 |
| **各步驟清單 Excel（每步一檔）** | 操作人員 | 見下方「給操作人員的清單」 |
| 驗收紀錄＋剩餘待辦 Excel | 資訊端、PM | 見 `acceptance.md`；格式另寫一份說明 |

每份文件都要有更新紀錄；狀態有變（完成、上線、核准）就同步更新進度欄。

## 簡明版的寫法

- 開頭**一段話**說明為什麼要做，不放驗證細節（驗證結果放操作步驟文件）。
- 一張表：順序、部門、修正內容、筆數、做法、**對應的清單檔名**。
- 表格後面接**各步驟操作注意事項**：共通規則＋每一步操作人員一定要知道的（不能做什麼、出現什麼要停、先做一張確認）。
- 說明哪些步驟可以同時進行、哪些要協調（先比對各步清單是否重疊）。
- 「需要 PM 協助」只留需要 PM 決定或安排的事。

## 給操作人員的清單（不要預設使用者會讀完整份 Excel）

- **每個步驟一個檔案、一個分頁**，只放那一步要處理的列；不處理的列不放進去。不要要求使用者在多分頁的總表裡自己篩選。
- **表格上方 2～3 行直接寫做法與注意事項**，不用另外翻文件也能操作。
- **欄位只留操作需要的，表頭用中文**；需要保留技術欄位代號時，用「中文＋換行＋代號」，並附欄位說明。
- 直接給**要改成的值**（「改成數量」「改成單位」，畫面上要輸入的值，例如 ST 寫 PC）；不用改的寫「不變」。
- 依急迫性排序（開工日／完工日），最急的在最上面；需要先確認的列用「注意」欄標出。
- 最後幾欄留處理結果、處理人、處理時間、備註。
- 同一張單據需要兩種修改時，合併到同一個檔案、同一列，避免兩個部門同時改同一張單。
