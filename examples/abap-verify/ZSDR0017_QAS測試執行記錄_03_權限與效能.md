## 執行 Checklist（逐案例）

### 第1步｜T21｜勾 `p_x`｜沒有改訂單權限的帳號能不能凍結

- [ ] 環境：QAS
- [ ] 準備測試資料：主表準備清單第 4 點的低權限帳號；再建一張 600,000 的測試訂單，記下前值
- [ ] 執行：用低權限帳號登入，只撈這張單，勾執行凍結
- [ ] 驗證：失敗的話緊接著跑 `SU53`；`SE16N` 查這張單的 `LIFSK`
- [ ] 核對是否符合預期：需確認：沒有訂單修改權限的人應該被擋下。如果凍結成功，就證明疑點 #2 成立
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第2步｜T22｜不勾 `p_x`｜`ST05` 看 LOOP 裡的重複查詢

- [ ] 環境：QAS
- [ ] 準備測試資料：一個 QAS 上訂單最多的月份
- [ ] 執行：`ST05` 開 SQL trace，跑報表（不勾執行凍結），跑完關 trace
- [ ] 驗證：`ST05` 看 Identical Selects 和 `KNA1`、`VBAP` 的執行次數
- [ ] 核對是否符合預期：`KNA1`、`VBAP` 的執行次數約等於訂單張數，同一位客戶的 `KNA1` 被重複讀。記下次數，和 T09 的 PRD 時間一起交給主管判斷要不要改
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第3步｜T23｜不勾 `p_x`｜建立日期跨年度

- [ ] 環境：QAS
- [ ] 準備測試資料：找 12 月底和 1 月初都有訂單的客戶
- [ ] 執行：建立日期填 12/25 到隔年 1/5
- [ ] 驗證：`SE16N` 用同樣條件查 `VBAK` 對張數
- [ ] 核對是否符合預期：兩個年度的單都列出，張數一致
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列
