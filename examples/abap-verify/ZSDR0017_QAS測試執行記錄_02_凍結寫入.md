# QAS 測試執行記錄：凍結寫入（T11–T20）

> 本檔案是 [ZSDR0017_QAS測試案例表](ZSDR0017_QAS測試案例表.md) 的執行記錄分冊，只放這個階段的案例與步驟。案例設計理由、高風險疑點、測試資料準備在主表。
> 這一冊會改訂單，只能在 QAS 跑。測試訂單 A～F 見主表「測試資料準備清單」。

## 執行 Checklist（逐案例）

### 第1步｜T11｜不執行｜記錄訂單 A～F 執行前的表頭

- [ ] 環境：QAS
- [ ] 準備測試資料：主表的訂單 A～F 都已建好
- [ ] 執行：本案例不執行動作，純記錄／比對用的基準
- [ ] 驗證：`SE16N` 查 `VBAK`，條件是這六張單號，把整列匯出 Excel 存檔（不只 `LIFSK`）
- [ ] 核對是否符合預期：六張單的交貨凍結 `LIFSK` 都是空白；不是空白就先清掉再記一次
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第2步｜T12｜勾 `p_x`｜500,001 的單被凍結

- [ ] 環境：QAS
- [ ] 準備測試資料：訂單 A
- [ ] 執行：`SE38` 跑 ZSDR0017，日期和客戶縮到只撈 A，**勾執行凍結**
- [ ] 驗證：ALV 的已凍結欄；`VA03` 看 A 的表頭交貨凍結；`SM13` 確認沒有失敗的 update
- [ ] 核對是否符合預期：ALV 標 X，訂單上是 Z1。和 T11 的前值比
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第3步｜T13｜勾 `p_x`｜剛好 500,000 的單不凍結

- [ ] 環境：QAS
- [ ] 準備測試資料：訂單 B，先在 `VA03` 確認表頭淨值剛好 500,000
- [ ] 執行：只撈 B，勾執行凍結
- [ ] 驗證：ALV 的已凍結欄；`SE16N` 查 B 的 `LIFSK`
- [ ] 核對是否符合預期：不凍結，因為程式是「大於」50 萬。需確認：業務的規則是「超過」還是「達到」50 萬
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第4步｜T14｜勾 `p_x`｜例外客戶 0000100023 的大單不凍結

- [ ] 環境：QAS
- [ ] 準備測試資料：訂單 C
- [ ] 執行：只撈 C，勾執行凍結
- [ ] 驗證：ALV 的已凍結欄；`SE16N` 查 C 的 `LIFSK`
- [ ] 核對是否符合預期：現行程式不凍結。需確認：這位客戶為什麼排除，規則現在還適用嗎
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第5步｜T15｜不勾 `p_x`｜沒勾就不能改任何訂單

- [ ] 環境：QAS
- [ ] 準備測試資料：訂單 D
- [ ] 執行：只撈 D，**不勾**執行凍結
- [ ] 驗證：`SE16N` 查 D 的整列，和 T11 的前值比
- [ ] 核對是否符合預期：整列完全沒變，ALV 的已凍結欄是空白
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第6步｜T16｜勾 `p_x`｜美元 20,000 的單不凍結

- [ ] 環境：QAS
- [ ] 準備測試資料：訂單 E（幣別 USD）
- [ ] 執行：只撈 E，勾執行凍結
- [ ] 驗證：ALV 的已凍結欄；`SE16N` 查 E 的 `LIFSK`
- [ ] 核對是否符合預期：現行程式不凍結，因為 20,000 小於 500,000，沒有換算台幣。需確認：門檻是不是應該用台幣計算
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第7步｜T17｜勾 `p_x`｜訂單被鎖住時，凍結失敗卻標成已凍結

- [ ] 環境：QAS
- [ ] 準備測試資料：訂單 F。另開一個視窗用 `VA02` 打開 F，停在畫面上不要存檔，讓訂單被鎖住
- [ ] 執行：只撈 F，勾執行凍結
- [ ] 驗證：ALV 的已凍結欄；關掉 `VA02` 後，`SE16N` 查 F 的 `LIFSK`；`SM13` 看 update
- [ ] 核對是否符合預期：正確的行為應該是不標記並顯示錯誤。現行程式預期會「ALV 標 X、訂單卻沒有 Z1」，出現這個結果就證明疑點 #1 成立
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第8步｜T18｜勾 `p_x`｜同樣的條件跑第二次

- [ ] 環境：QAS
- [ ] 準備測試資料：沿用 T12 已凍結的訂單 A
- [ ] 執行：用 T12 的條件再跑一次，勾執行凍結
- [ ] 驗證：ALV 的已凍結欄；`SE16N` 查 A 的整列；`SM13`
- [ ] 核對是否符合預期：不出錯，A 仍是 Z1，其他欄位和第一次跑完一樣。報表一樣標 X，分不出是不是這次新凍結的（規格書 5.3 邊界條件 2）
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第9步｜T19｜不執行｜前後值比對，只有交貨凍結變了

- [ ] 環境：QAS
- [ ] 準備測試資料：T12～T18 都跑完
- [ ] 執行：本案例不執行動作，純記錄／比對用的基準
- [ ] 驗證：`SE16N` 用 T11 的同一個條件再匯出一次 `VBAK`，和 T11 的 Excel 逐欄比對
- [ ] 核對是否符合預期：只有 A 的 `LIFSK` 變成 Z1，以及異動日期、異動人這類系統欄位；其他欄位有變就是 bug
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第10步｜T20｜勾 `p_x`｜跑到一半中斷

- [ ] 環境：QAS
- [ ] 準備測試資料：需要至少 20 張超過 50 萬的測試單，才來得及在中途中斷。準備不出來就暫緩
- [ ] 執行：勾執行凍結，跑到一半用 `SM50` 中止這個工作程序
- [ ] 驗證：`SE16N` 查這批單的 `LIFSK`
- [ ] 核對是否符合預期：前面的單已凍結、後面的沒有，報表沒有留下停在哪一張的紀錄（身分證 #3）
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列
