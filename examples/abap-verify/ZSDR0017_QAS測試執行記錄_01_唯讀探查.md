## 執行 Checklist（逐案例）

### 第1步｜T01｜不勾 `p_x`｜一個客戶、一週的訂單，報表明細和訂單一致

- [ ] 環境：QAS
- [ ] 準備測試資料：挑一個 QAS 上近期有 ZOR 訂單的客戶，記下那一週的訂單號碼
- [ ] 執行：`SE38` 跑 ZSDR0017，建立日期填那一週、客戶填這一位，**不勾執行凍結**
- [ ] 驗證：挑兩張單，用 `VA03` 對每個項目的料號、數量、淨值
- [ ] 核對是否符合預期：每個項目一列，欄位和 `VA03` 一致
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第2步｜T02｜不勾 `p_x`｜報表的項目數和金額合計，和 `SE16N` 撈的一致

- [ ] 環境：QAS
- [ ] 準備測試資料：沿用 T01 的條件
- [ ] 執行：ALV 用合計功能算出筆數和金額合計
- [ ] 驗證：`SE16N` 先查 `VBAK`（同樣的日期、客戶、VKORG = TW01、AUART = ZOR／ZOR2）拿到訂單號碼，再查 `VBAP` 算筆數和 NETWR 合計
- [ ] 核對是否符合預期：筆數、金額完全一致；不一致就記下差在哪幾張單
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第3步｜T03｜不勾 `p_x`｜已全部出貨的訂單仍會列出

- [ ] 環境：QAS
- [ ] 準備測試資料：依主表「測試資料準備清單」第 3 點找一張已全部出貨的 ZOR 訂單
- [ ] 執行：用這張單的建立日期和客戶跑報表
- [ ] 驗證：ALV 裡找這張單號
- [ ] 核對是否符合預期：現行程式會列出（規格書 5.1）。需確認：業務要的「未結」是否應該排除這張單
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第4步｜T04｜不勾 `p_x`｜有拒絕原因的項目仍會列出

- [ ] 環境：QAS
- [ ] 準備測試資料：找一張有項目帶拒絕原因（`VBAP-ABGRU` 不是空白）的 ZOR 訂單
- [ ] 執行：用這張單的建立日期和客戶跑報表
- [ ] 驗證：ALV 裡找那個項目
- [ ] 核對是否符合預期：現行程式會列出，因為 CR-0347 的條件被註解掉。需確認：被拒絕的項目要不要排除
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第5步｜T05｜不勾 `p_x`｜撈不到任何訂單時不 dump

- [ ] 環境：QAS
- [ ] 準備測試資料：一個未來的日期區間，確定沒有訂單
- [ ] 執行：建立日期填那個區間
- [ ] 驗證：看畫面，`ST22` 確認沒有新的 dump
- [ ] 核對是否符合預期：出現空的 ALV 或「沒有資料」，不 dump
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第6步｜T06｜不勾 `p_x`｜客戶主檔讀不到時，客戶名稱沿用上一張單

- [ ] 環境：QAS
- [ ] 準備測試資料：需確認：QAS 能不能造出「訂單上有、`KNA1` 讀不到」的客戶。正常系統不允許，造不出來就停在這一步
- [ ] 執行：造得出來的話，讓這張單排在另一位客戶的單後面，跑報表
- [ ] 驗證：ALV 裡這張單的客戶名稱欄
- [ ] 核對是否符合預期：現行程式會顯示上一張單的客戶名稱（規格書 5.2）。造不出資料就在追蹤表記「無法重現，以程式碼為證」
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第7步｜T07｜不勾 `p_x`｜其他銷售組織、其他訂單類型不會列出

- [ ] 環境：QAS
- [ ] 準備測試資料：`SE16N` 找同一位客戶在其他銷售組織，或其他訂單類型的訂單
- [ ] 執行：用涵蓋這些訂單的日期和客戶跑報表
- [ ] 驗證：ALV 裡找這些單號
- [ ] 核對是否符合預期：不會出現
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第8步｜T08｜不勾 `p_x`｜單一項目、多項目的訂單都正確展開

- [ ] 環境：QAS
- [ ] 準備測試資料：找一張只有一個項目、一張有五個以上項目的 ZOR 訂單
- [ ] 執行：一次撈到這兩張單
- [ ] 驗證：`VA03` 對項目數
- [ ] 核對是否符合預期：每張單的列數等於項目數，沒有漏列、沒有重複列
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第9步｜T09｜不勾 `p_x`｜真實資料量跑一個月，記執行時間

- [ ] 環境：PRD，只能唯讀
- [ ] 準備測試資料：不用準備。執行前再確認一次選擇畫面上**執行凍結沒有勾**
- [ ] 執行：建立日期填最近一個月，客戶不填，前景執行
- [ ] 驗證：記下執行時間和 ALV 筆數；超過 10 分鐘就中止，改在 QAS 用 `ST05` 找原因（T22）
- [ ] 核對是否符合預期：需確認：使用者實際查詢的日期範圍有多大，能接受多久
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列

### 第10步｜T10｜不執行｜背景排程的變式有沒有勾 `p_x`

- [ ] 環境：PRD，只能唯讀
- [ ] 準備測試資料：不用準備
- [ ] 執行：本案例不執行動作，純記錄／比對用的基準
- [ ] 驗證：`SM37` 用程式名稱 ZSDR0017 查 Job；有的話到 `SE38` 看它用的變式
- [ ] 核對是否符合預期：記下有沒有 Job、多久跑一次、變式有沒有勾執行凍結。有勾的話，這支程式在正式區定期自動凍結訂單，要立刻告訴主管
- [ ] 回填到[總追蹤表](ZSDR0017_QAS測試案例表.md#測試執行追蹤表)對應這個案例那一列
