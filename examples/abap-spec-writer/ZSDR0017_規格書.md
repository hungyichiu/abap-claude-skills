## 2. 需求背景與目的

**目前程式做的兩件事：**

1. 列出台灣銷售組織一般訂單的每一個項目：訂單號碼、客戶、料號、數量、金額。
2. 使用者勾選「執行凍結」時，整張訂單金額超過 50 萬的，系統自動在訂單上設交貨凍結，讓這張單不能出貨，等人工放行。

**這支程式原本要解決的問題（待確認）：**

- 標頭寫的是「未結訂單報表」，2015 年的 CR-0347 要求「只顯示未出貨項目」。
- 但現行程式沒有任何出貨狀態的篩選，已出貨、已完成的訂單也會列出來。
- 「未結」指的是未出貨、未開票還是未完成，要請需求方定義。這會決定報表要不要改。

**凍結功能的目的（待確認）：** 推測是大額訂單出貨前要先經過信用或主管確認。50 萬門檻和例外客戶的來源，程式裡沒有說明。

**驗收標準（以現行行為為準，需求方確認後再修訂）：**

1. 輸入建立日期和客戶範圍，報表列出的項目與系統上的訂單項目一致。
2. 勾選執行凍結後，整張單金額超過 50 萬的訂單，在訂單上看得到凍結碼 Z1。
3. 沒勾選時，程式只顯示資料，不會改任何訂單。

## 3. 名詞定義

| 名詞 | 意思 |
|---|---|
| 銷售組織 TW01 | 負責台灣銷售的組織單位，程式只看這一個。 |
| 訂單類型 ZOR／ZOR2 | 公司自訂的兩種訂單類型，程式只看這兩種。 |
| 交貨凍結 | 設在訂單上的標記，有標記的訂單不能建立出貨單，要人工解除。 |
| 凍結碼 Z1 | 程式設的交貨凍結原因代碼，業務含義待確認。 |
| 整張單淨額 | 同一張訂單所有項目金額（不含稅）的加總，用訂單本身的幣別計算。 |
| BAPI | SAP 提供的標準功能介面，程式透過它修改訂單，效果跟人工在訂單畫面修改相同。 |
| ALV | SAP 的表格式報表畫面，可以排序、篩選、匯出 Excel。 |

## 4. 功能範圍

### 4.1 選擇畫面

| 欄位 | 對應資料 | 必填/選填 | 說明 |
|---|---|---|---|
| 訂單建立日期 | 訂單表頭的建立日期 | 選填 | 可輸入區間。不輸入會撈所有日期，資料量可能很大，建議一律輸入。 |
| 客戶 | 訂單表頭的售達客戶 | 選填 | 可輸入多個或區間。不輸入代表全部客戶。 |
| 執行凍結 | 勾選框 | 選填 | 勾選才會修改訂單，沒勾只顯示報表。畫面上的技術名稱是 `p_x`，看不出用途，操作時要特別注意。 |

銷售組織 TW01、訂單類型 ZOR／ZOR2 寫在程式裡，畫面上不能改。

### 4.2 處理流程總覽

1. 依選擇畫面條件，加上固定的銷售組織和訂單類型，撈出訂單表頭。
2. 逐張訂單讀出客戶名稱和全部項目，每個項目放一列報表。
3. 同時加總整張單的項目金額。
4. 有勾選執行凍結、而且符合凍結條件的訂單，設交貨凍結 Z1，並在報表上標記。
5. 顯示報表。

## 5. 處理邏輯設計

### 5.1 撈取訂單

只看銷售組織 TW01、訂單類型 ZOR 或 ZOR2 的訂單，再套用畫面上的建立日期和客戶。

不篩選出貨、開票或完成狀態，也不排除被拒絕的項目。

> **核心規則：報表範圍不等於「未結訂單」**
>
> 已出貨、已完成、項目被拒絕的訂單都會出現在報表上。
>
> 例：一張 3 月建立、3 月已全部出貨的訂單，查 3 月時照樣會列出它的每一個項目。
>
> 需求方定義「未結」之前，不要拿這份報表當未結清單用。

### 5.2 組報表明細

每個訂單項目一列，帶出訂單號碼、建立日期、客戶、客戶名稱、項目號碼、料號、數量、金額。

客戶名稱從客戶主檔讀取。

**已知限制：** 客戶主檔讀不到某位客戶時，這一列會顯示「上一張訂單的客戶名稱」，不會留白。客戶主檔正常的情況下不會發生，但看到名稱和客戶代號對不上時，要以客戶代號為準。

### 5.3 大額訂單交貨凍結

> **核心規則：三個條件同時成立才凍結**
>
> 1. 選擇畫面有勾選執行凍結。
> 2. 整張單淨額大於 500,000（剛好等於不凍結）。
> 3. 客戶不是 0000100023。
>
> 三個條件都成立，程式在訂單上設交貨凍結 Z1，並把這張單的每一列都標記為已凍結。

| 情境 | 整張單淨額 | 客戶 | 有勾執行凍結 | 結果 |
|---|---|---|---|---|
| 一般大額單 | 500,001 | 0000100001 | 是 | 凍結 |
| 剛好等於門檻 | 500,000 | 0000100001 | 是 | 不凍結 |
| 例外客戶 | 900,000 | 0000100023 | 是 | 不凍結 |
| 沒勾選 | 900,000 | 0000100001 | 否 | 不凍結，只顯示 |

**邊界條件：**

1. **幣別：** 門檻用訂單本身的幣別比較，沒有換算。一張 20,000 美元的訂單不會凍結；一張 600,000 日圓的訂單會凍結。門檻是否應該統一用台幣，待確認。
2. **重複執行：** 已經凍結的訂單再跑一次，程式會再設一次 Z1，報表照樣標記已凍結。不會出錯，但報表上分不出哪些是這次新凍結的。
3. **凍結失敗：** 訂單被別人開著修改、或凍結碼不能用時，凍結不會成功，但報表一樣會標記已凍結。目前要回訂單上確認凍結碼，才能知道有沒有真的設上去。
4. **中途中斷：** 每張單凍結後立即存檔。程式跑到一半中斷，前面的單已凍結、後面的沒有，報表不會留下停在哪一張的紀錄。

## 6. 輸出欄位定義

| 欄位 | 對應資料型別 | 說明 |
|---|---|---|
| 訂單號碼 | VBAK-VBELN | 同一張訂單的每個項目各佔一列，訂單號碼會重複出現。 |
| 建立日期 | VBAK-ERDAT | 訂單表頭的建立日期，不是項目的交貨日期。 |
| 客戶 | VBAK-KUNNR | 售達客戶代號。和客戶名稱對不上時以這欄為準（見 5.2）。 |
| 客戶名稱 | KNA1-NAME1 | 客戶主檔的名稱第一行。 |
| 項目 | VBAP-POSNR | 訂單項目號碼。 |
| 料號 | VBAP-MATNR | 這個項目的物料。 |
| 數量 | VBAP-KWMENG | 訂單數量，單位是訂單上的銷售單位，報表沒有顯示單位欄。 |
| 金額 | VBAP-NETWR | 項目淨額，不含稅，訂單幣別。報表沒有顯示幣別欄，不同幣別的訂單不能直接加總。 |
| 已凍結 | 一碼字元 | X 表示這次執行時程式對這張單送出了凍結。不保證凍結真的成功（見 5.3 邊界條件 3）。 |

報表畫面使用的欄位結構 ZSDS0017 是否和上表完全一致，待確認。
