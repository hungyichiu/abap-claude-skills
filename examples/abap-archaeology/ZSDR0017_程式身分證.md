# 程式身分證：ZSDR0017

> 依 legacy ABAP 常見問題寫成的示範程式，不含任何公司資料。本次無背景檔、未讀到知識庫，以下推測僅基於程式碼。
> ✅ 事實　🔶 推測　❓ 未知

## 一、先看這裡

### 一句話總結
🔶 列出銷售組織 TW01 的 ZOR/ZOR2 訂單明細；勾選 p_x 時，會把整張單淨額超過 50 萬的訂單直接設交貨凍結 Z1。

### 🔥 摘要

**宣稱 vs 實際**
- 標頭說「未結訂單、只顯示未出貨項目」，實際上沒有任何狀態過濾：已出貨、已完成的訂單全部會列出。CR-0347 那行被註解掉了，而且它過濾的是拒絕原因，不是出貨狀態。

**最高風險**
- 這支「報表」會改正式資料：勾 p_x 就呼叫 BAPI 改訂單表頭。
- BAPI 沒檢查 RETURN 就 COMMIT，失敗也會被標成已凍結。
- 沒有 AUTHORITY-CHECK，任何能跑程式的人都能凍結訂單。

**卡住就無法繼續的問題**
- 🔥 p_x 現在有沒有人在勾？背景 Job 有沒有帶這個變式？
- 🔥 「未結」業務上的定義是什麼？CR-0347 為什麼被註解掉？
- 🔥 客戶 0000100023 為什麼不凍結？

## 二、程式行為

### 基本資料
| 項目 | 內容 |
|---|---|
| 物件 | ZSDR0017 / Report |
| 原作者 | WLIN（2014） |
| 修改記錄 | 2014/03/12 WLIN 新建 |
| | 2015/08/05 WLIN CR-0347 只顯示未出貨 |
| | 2016/11/20 KCHEN 大額訂單自動凍結 |
| 行數 | 93 行，單一主流程，無 FORM |

### ⚠️ 宣稱 vs 實際
宣稱：未結訂單報表，且 CR-0347 加上「只顯示未出貨項目」。

實際：✅ 程式完全沒讀出貨或處理狀態，只要符合日期、客戶、銷售組織、訂單類型就列出。

```abap
*     AND abgru = space.          "CR-0347
```

✅ CR-0347 的條件被註解掉，從未生效。🔶 就算打開，ABGRU 是「拒絕原因」，也只能排除被拒絕的項目，跟「未出貨」不是同一件事。

另外 ✅ 標頭只寫「大額訂單自動凍結」，沒提到門檻 50 萬和例外客戶，這些規則只存在程式碼裡。

### 輸入
| 欄位 | 意義 | 確定性 |
|---|---|---|
| s_erdat | 訂單建立日期 | ✅ |
| s_kunnr | 售達客戶 | ✅ |
| p_x | 勾了才執行自動凍結 | ✅ 行為／🔶 命名完全看不出 |

### 處理流程
1. 撈 VBAK：日期、客戶範圍，加上寫死的 TW01、ZOR/ZOR2。
2. 逐張訂單 LOOP：每張單各讀一次 KNA1 客戶名、VBAP 全部項目。
3. 加總整張單的項目淨額，項目逐筆放進輸出表。
4. p_x 勾選、淨額 > 500000、客戶不是 0000100023：呼叫 BAPI 設交貨凍結 Z1，立刻 COMMIT，輸出表標 flag。
5. ALV 顯示。

### 輸出
- ✅ ALV（結構 ZSDS0017）
- ✅ 更新訂單表頭交貨凍結（透過 BAPI）

### 風險與可疑點
1. **BAPI 失敗被吞掉（76–85 行）**：訂單被別人鎖住或凍結碼不合法時，BAPI 回錯誤訊息，程式照樣 COMMIT、照樣標 flag。使用者看 ALV 會以為凍結成功，實際沒凍結，大額訂單照常出貨。
2. **沒有 AUTHORITY-CHECK**：只要有 SE38/T-code 權限就能凍結 TW01 全部大額訂單。稽核常見缺失。
3. **COMMIT 在 LOOP 內（83 行）**：跑到一半中斷，前面的單已凍結、後面沒有，沒有紀錄可以知道停在哪。
4. **LOOP 裡 SELECT（51、54 行）**：每張單兩次 DB 存取，日期範圍一放大就可能 timeout。
5. **讀 KNA1 沒檢查 sy-subrc、沒 CLEAR（51 行）**：讀不到時沿用上一張單的客戶名，ALV 會出現名字錯的列。
6. **寫死的值**：TW01、ZOR/ZOR2、500000、Z1、0000100023。換銷售組織或改門檻都要改程式。
7. 🔶 **50 萬沒管幣別**：NETWR 是訂單幣別，USD 單和 TWD 單用同一個門檻。
8. 🔶 **ls_hd 沒有每圈 CLEAR**：目前只放一個欄位影響不大，日後加欄位就會帶到下一張單。
