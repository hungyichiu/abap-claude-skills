## 二、事實

### 回報內容

2026-10-15 業務回報：訂單 `0000045821`（客戶 `0000100587`）金額 20,000 美元，10/14 建立、10/15 出貨，沒有被交貨凍結。信用管理問程式為什麼沒擋。

### 程式在做什麼（程式碼判讀）

1. 🔶 背景 job 每天跑，勾 `p_x` 時，整張單 `VBAP-NETWR` 加總超過 500,000、客戶不是 `0000100023`，就呼叫 `BAPI_SALESORDER_CHANGE` 設交貨凍結 `Z1`（72～85 行）。
2. 🔶 第 84 行不管 BAPI 成功或失敗都會把輸出的 `flag` 標成 `X`。
	- 反過來說：輸出裡 `flag` 空白，代表程式根本沒進第 72 行的 IF。
3. 🔶 程式身分證「風險與可疑點」第 7 點已經寫過「50 萬沒管幣別」，當時是推測，沒用資料驗證。

### 用系統紀錄確認的事實

1. ✅ 背景 job：`TBTCO`／`TBTCP` 查到 job `ZSDR0017_BLOCK` 每天 07:00 跑一次，變式 `BLOCK`，`p_x` 有勾，`s_erdat` 是動態的「今天往前 30 天」（S1）。
2. ✅ 10/15 07:00 那次 job 的輸出（spool）有列出 `0000045821`，`flag` 空白。
3. ✅ 版本紀錄：`VRSD` 最後一版是 2016/11/20 KCHEN，之後沒有傳輸。問題不是最近上線的修改造成的。

## 三、找原因

### H1：BAPI 執行失敗，程式沒看 RETURN

這是程式身分證列的最高風險，先查它。

1. ✅ spool 裡 `0000045821` 的 `flag` 空白。依第二節第 2 點，程式沒有呼叫 BAPI。
2. ✅ `CDHDR`／`CDPOS`（`OBJECTCLAS = 'VERKBELEG'`）查這張單：沒有任何 `LIFSK` 的變更紀錄（S2）。
3. 「查無紀錄」不能直接當成「沒人動過」，所以先確認這張表有寫變更紀錄：
	- ✅ 同一次 job 凍結的 `0000045790` 有一筆 `LIFSK` 空白 → `Z1`，使用者是 job 的執行帳號，時間 07:00:42。
	- 訂單表頭的交貨凍結有寫變更紀錄，`0000045821` 查無紀錄是真的沒被改過。

結論：✅ 排除。程式根本沒試著凍結這張單。

### H2：這個客戶是寫死的例外客戶

1. ✅ `VBAK-KUNNR` 是 `0000100587`，不是程式裡寫死的 `0000100023`。

結論：✅ 排除。

### 兩個假設都被推翻：回頭補事實

不提第三個假設，改找對照組：同一次 job、同一天建立、**有被凍結**的大單，跟 `0000045821` 並排比對所有欄位（S3）。

| 欄位 | `0000045790`（有凍結） | `0000045821`（沒凍結） |
|---|---|---|
| 銷售組織 `VKORG` | TW01 | TW01 |
| 訂單類型 `AUART` | ZOR | ZOR |
| 建立日 `ERDAT` | 2026-10-14 | 2026-10-14 |
| 客戶 `KUNNR` | 0000100412 | 0000100587 |
| 幣別 `WAERK` | TWD | USD |
| `VBAP-NETWR` 加總 | 620,000 | 20,000 |
| 交貨凍結 `LIFSK` | Z1 | 空白 |

除了單號、客戶這些本來就不同的欄位，只剩幣別和金額不一樣。

### H3：門檻沒管幣別

1. 🔶 程式碼：第 68 行 `lv_sum` 加總的是訂單幣別的 `NETWR`，第 72 行直接跟 500,000 比，中間沒有換算。
2. ✅ 用資料驗證（S4）：2016/11 以來 TW01 的 ZOR／ZOR2 訂單，依幣別統計被凍結的張數。
	- TWD：加總超過 500,000 的 1,284 張，凍結 1,276 張（另外 8 張是例外客戶）。
	- USD、EUR：凍結 0 張，數字最大的一張是 98,500 USD。
3. ✅ 機制跟資料對得上：非台幣訂單的數字小一個數量級，永遠到不了門檻。

結論：✅ 成立。

## 五、對策

### 1. 要信用管理決定的事

1. ❓ 換算用哪種匯率：每日匯率還是月平均。
2. ❓ 用哪一天的匯率：訂單建立日還是程式執行日。
3. ❓ 門檻要不要依幣別各設一個值，取代換算。

這三題沒定，程式不動。不自己挑一個看起來合理的答案。

### 2. 程式修正（走 CR）

1. 第 72 行比較前，用 `CONVERT_TO_LOCAL_CURRENCY` 把 `lv_sum` 換成台幣再比，匯率類型和日期照信用管理決定的填。
2. 同一個 CR 建議順便修程式身分證的最高風險：檢查 BAPI 的 `RETURN`，失敗就不 `COMMIT`、不標 `flag`。
	- 這次的原因不是它，但修正版要上線，一起改只需要測一次。是否納入，由 CR 決定。

### 3. QAS 驗證修正版

| # | 情境 | 預期 |
|---|---|---|
| V1 | USD 20,000（換算約 64 萬） | 凍結 |
| V2 | USD 15,000（換算約 48 萬） | 不凍結 |
| V3 | TWD 500,000（剛好等於門檻） | 不凍結（條件是大於） |
| V4 | TWD 620,000 | 凍結，結果跟修正前一樣 |
| V5 | 例外客戶 `0000100023`，USD 30,000 | 不凍結 |

每一案都記執行前、執行後的 `LIFSK`，和 `CDPOS` 的變更紀錄。

### 4. 修正前的作業規則

修正版上線前，信用管理每天早上跑一次 S5，手動用 `VA02` 凍結新出現的非台幣大單。

## 六、修復與收尾

順序：清單已匯出（第四節）→ QAS 驗證修正版（第五節第 3 點）→ 修正版上線 → 處理資料。

1. **為什麼程式先上線**：舊程式還在跑，每天都有新的非台幣訂單漏掉，先修資料，清單隔天就過期。
	- L1 的 2 張建立日都在變式的 30 天內，修正版上線後第一次 job 就會凍結它們，不用另外手動改。
2. **上線後第一次 job 跑完**：重跑 S5，L1 應該是 0；`CDPOS` 要看到這 2 張的 `LIFSK` 空白 → `Z1`。
3. **監控**：上線後第一週每天跑 S5，之後每週一次，非台幣、換算超過 50 萬、未凍結、未出貨的應該一直是 0。
4. **L2**：照信用管理的決定處理，結果補在這裡。

## 附錄：用過的 SQL

在 DBACOCKPIT 執行。`<client>` 換成正式區的 client。

### S1：job 的執行紀錄

```sql
SELECT o.JOBNAME, o.SDLUNAME, p.PROGNAME, p.VARIANT, COUNT(*) AS RUNS, MIN(o.STRTDATE) AS FIRST_RUN, MAX(o.STRTDATE) AS LAST_RUN
FROM TBTCO o
JOIN TBTCP p ON p.JOBNAME = o.JOBNAME AND p.JOBCOUNT = o.JOBCOUNT
WHERE o.AUTHCKMAN = '<client>' AND p.PROGNAME = 'ZSDR0017' AND o.STRTDATE >= '20260901'
GROUP BY o.JOBNAME, o.SDLUNAME, p.PROGNAME, p.VARIANT;
```

### S2：交貨凍結的變更紀錄（問題單＋對照單）

```sql
SELECT h.OBJECTID, h.USERNAME, h.UDATE, h.UTIME, h.TCODE, p.FNAME, p.VALUE_OLD, p.VALUE_NEW
FROM CDHDR h
JOIN CDPOS p ON p.MANDANT = h.MANDANT AND p.OBJECTCLAS = h.OBJECTCLAS AND p.OBJECTID = h.OBJECTID AND p.CHANGENR = h.CHANGENR
WHERE h.MANDANT = '<client>' AND h.OBJECTCLAS = 'VERKBELEG' AND h.OBJECTID IN ('0000045821', '0000045790') AND p.FNAME = 'LIFSK'
ORDER BY h.OBJECTID, h.UDATE, h.UTIME;
```

### S3：對照組並排

```sql
SELECT k.VBELN, k.VKORG, k.AUART, k.ERDAT, k.KUNNR, k.WAERK, k.LIFSK, SUM(p.NETWR) AS SUM_NETWR
FROM VBAK k
JOIN VBAP p ON p.MANDT = k.MANDT AND p.VBELN = k.VBELN
WHERE k.MANDT = '<client>' AND k.VBELN IN ('0000045821', '0000045790')
GROUP BY k.VBELN, k.VKORG, k.AUART, k.ERDAT, k.KUNNR, k.WAERK, k.LIFSK;
```

### S4：依幣別統計凍結張數

```sql
SELECT t.WAERK, COUNT(*) AS ORDERS, SUM(CASE WHEN t.LIFSK = 'Z1' THEN 1 ELSE 0 END) AS BLOCKED, MAX(t.SUM_NETWR) AS MAX_NETWR
FROM (
  SELECT k.VBELN, k.WAERK, k.LIFSK, SUM(p.NETWR) AS SUM_NETWR
  FROM VBAK k
  JOIN VBAP p ON p.MANDT = k.MANDT AND p.VBELN = k.VBELN
  WHERE k.MANDT = '<client>' AND k.VKORG = 'TW01' AND k.AUART IN ('ZOR', 'ZOR2') AND k.ERDAT >= '20161120'
  GROUP BY k.VBELN, k.WAERK, k.LIFSK
) t
WHERE (t.WAERK = 'TWD' AND t.SUM_NETWR > 500000) OR t.WAERK <> 'TWD'
GROUP BY t.WAERK;
```

### S5：影響範圍（L1／L2）

固定匯率只用來圈範圍。`GBSTK` 是整張單的處理狀態，`C` 是已完成。

```sql
SELECT t.*, CASE WHEN t.GBSTK = 'C' THEN 'L2_SHIPPED' ELSE 'L1_OPEN' END AS LIST
FROM (
  SELECT k.VBELN, k.ERDAT, k.KUNNR, k.WAERK, k.LIFSK, k.GBSTK, SUM(p.NETWR) AS SUM_NETWR,
         SUM(p.NETWR) * CASE k.WAERK WHEN 'USD' THEN 32 WHEN 'EUR' THEN 35 ELSE 0 END AS EST_TWD
  FROM VBAK k
  JOIN VBAP p ON p.MANDT = k.MANDT AND p.VBELN = k.VBELN
  WHERE k.MANDT = '<client>' AND k.VKORG = 'TW01' AND k.AUART IN ('ZOR', 'ZOR2') AND k.WAERK <> 'TWD' AND k.KUNNR <> '0000100023' AND k.LIFSK = ''
  GROUP BY k.VBELN, k.ERDAT, k.KUNNR, k.WAERK, k.LIFSK, k.GBSTK
) t
WHERE t.EST_TWD > 500000
ORDER BY t.ERDAT;
```

🔶 S/4HANA 的整張單狀態在 `VBAK`（`VBUK` 已停用）；ECC 要改 join `VBUK` 取 `GBSTK`。
